# Content Pulse 2.0

Витрина съёмок поверх Яндекс Диска компании. Работает в браузере, одинаково на Windows и Mac.
Своего сервера и базы нет: файлы и состояние лежат на Диске клиента, программа их показывает и раскладывает.

- **Каталог.** В настройках задаётся одна папка — КАТАЛОГ. Внутри неё папки этапов: 01 исходники, 02 согласование, 03 ретушь, 04 отретушировано, 05 сайт. Статус кадра — это папка, в которой лежит его файл.
- **Витрина:** съёмки из исходников, фильтры = папки этапов, под съёмкой — где сейчас её артикулы.
- **Съёмка:** галерея прямо с Диска, отбор в карточки (движок Cardboard), карточки товара по папкам артикулов.
- **Общий отбор:** `<съёмка>/_contentpulse.json`, виден всем. Одновременные правки склеиваются, версии отбора — в `_ContentPulse/версии отборов/`.
- **Этапы:** на согласование — копия в 02, на ретушь — копия в 03, сдача ретуши — в 04, «На сайт» — перенос 04 → 05.
- **Скачивание:** архив собирает прослойка в Yandex Cloud и кладёт в облачное хранилище на 3 дня.
- **Настройки клиента:** `КАТАЛОГ/_ContentPulse/` — `теги.txt`, `структура.txt`, `настройки.txt`.
- **Журнал:** кто, что и когда сделал.

Нет папки этапа в каталоге — программа говорит об этом («Исправить папки» на витрине) и ничего не делает. Старые пути (`<съёмка>/Ретушь`, `<съёмка>/_приёмка`) работают только для обычного архива без каталога.

## Устройство

Скрипты подключаются в этом порядке; каждый следующий может дополнять функции предыдущих.

| Файл | Что внутри |
|---|---|
| `index.html` | основа Cardboard: вёрстка карточек, шаблоны, галерея, печать A4, экспорт списка, референсы |
| `cp-disk.js` | клиент API Яндекс Диска и прослойки: повторы, копии, перенос, Корзина, файл отбора с проверкой ревизии |
| `cp-app.js` | ядро: вход через Яндекс, витрина, открытие съёмки, сохранение и склейка отбора, статусы, журнал, скачивание |
| `cp-shelf.js` | панель съёмки на витрине, словарь тегов, настройки |
| `cp-rules.js` | `структура.txt`: типы съёмок, артикулы, карточки по папкам артикулов; редактор файлов настроек |
| `cp-guard.js` | правила отбора после ретуши, теги карточек, большой «+», проверка новой версии, запуск |
| `cp-deliver.js` | выдача ретушёрам галочками, статусы пачкой |
| `cp-stages.js` | сводка съёмки в свойствах её папки, фильтры витрины |
| `cp-accept.js` | окно «Сдать», версии ретуши (без каталога — приёмка в `<съёмка>/_приёмка`) |
| `cp-mirror.js` | сверка отбора с папками этапов |
| `cp-catalog.js` | КАТАЛОГ: роли папок 00–05, «Исправить папки», проверка папки этапа перед действием |
| `cp-review.js` | 02 согласование, 04 → 05, доработка, скачивание по этапам |
| `cp-site.js` | вкладка «Сайт»: даты и «скачано» |
| `cp-upload.js` | загрузка съёмки в исходники |
| `cp-speed.js` | проверка скорости загрузки и скачивания |
| `proxy/index.js` | прослойка (Yandex Cloud Function): превью, копии, перенос, Корзина, сборка ZIP |

Настройки программы — в начале `cp-app.js` (`CP_CONFIG`). Версии — `CHANGELOG.md`, выпуск — `tools/release.py`, откат — `tools/rollback.md`.

## Проверка

```bash
node tests/e2e.js   # браузер + подменённый API Диска
```

На настоящем Диске проверяется вручную: вход, витрина, открытие съёмки, ретушь, скачивание.
